# FocusGuard host protocol (v1)

> Copy of the keyboard firmware's [`docs/PROTOCOL.md`](https://github.com/illixion/qmk_firmware/blob/illixion/keyboards/ducky/one2sf/1967st/ansi/keymaps/illixion/docs/PROTOCOL.md); `tools/` and `host/` paths below are in that firmware tree.

32-byte raw HID packets on usage page `0xFF60`, usage `0x61` (the same interface
QMKD/OpenRGB use). Byte 0 is the command; commands `0xB0..0xBF` belong to this
protocol. Constants live in [`../fg/fg_proto.h`](https://github.com/illixion/qmk_firmware/blob/illixion/keyboards/ducky/one2sf/1967st/ansi/keymaps/illixion/fg/fg_proto.h).

Every response is `[cmd, status, ...]`. Status: `0` ok, `1` authentication failed,
`2` replay, `3` unavailable (no key in this build), `4` bad arguments, `5` not active,
`6` cooldown (Esc closed a stream less than 10 s ago).

## Per-key LED overrides (open, no key needed)

Cosmetic and unauthenticated by design: anything on the Mac can already draw on the
keyboard through OpenRGB. Overrides are RAM-only and are drawn **after** the animation
and after any QMKD/OpenRGB host frame on every frame, so they persist through every
effect. Draw order, top wins: stream indicator (red pulse), Caps/passthrough whites, overrides,
OpenRGB frame, animation. Privacy blackout hides everything except the stream indicator.

| Cmd | Request | Response |
|---|---|---|
| `0xB0` STATUS | – | `[ver, flags, led_count, overridden, last_ctr[6]]` (flags: 1 key provisioned, 2 stream active) |
| `0xB1` LED_SET | `ttl_hi ttl_lo n {led r g b}*n` (n ≤ 7, ttl seconds, 0 = until reset) | `[status, applied]` |
| `0xB2` LED_RESET | `n {led}*n` (n = 0 resets everything) | `[status]` |
| `0xB3` LED_GET | `led` | `[status, led, active, r, g, b, ttl_hi, ttl_lo]` |

LED indices and the key under each come from QMKD `GET_LED_MAP`; `host/kbled` does the
name lookup (`kbled set esc,a red --ttl 60`, `kbled reset --all`).

## Secure keystroke stream (authenticated + encrypted)

### Why it exists
macOS Secure Event Input (password fields, `pinentry`, Terminal "Secure Keyboard Entry")
hides keystrokes from every non-privileged reader. A Mac-side bridge that re-types keys
stolen by Universal Control is therefore blind exactly when a password is typed. The
keyboard can relay the keys on its vendor interface, which is not a keyboard usage page.

### Why that is dangerous, and what changed
The first version (`0xA3`, now **removed**) streamed `[0xEE, pressed, keycode, mods]` in
clear, switched on by an unauthenticated command. Reading a vendor HID interface needs no
Input Monitoring grant, so **any process running as the user could have enabled it and
logged every keystroke, passwords included**, bypassing both Secure Event Input and TCC.
`0xA4` (native-report suppression) could likewise be switched on by anyone to make the
keyboard type nothing. Both are gone.

### Design
* **Key.** 256 random bits, generated by `tools/fg-provision.sh` and stored **only** in the
  login Keychain, with FocusGuard as the one app allowed to read it without a prompt.
  `tools/fg-flash.sh` reads it (you approve the prompt), writes it to `fg_device_key.h` in a
  private temporary directory passed to the build as `FG_KEY_DIR`, builds only the `.elf`
  there (QMK's `.bin` rules would copy the image into the repo root), converts and flashes
  it, and deletes the directory. No file in the repo, the build tree or the repo root ever
  holds the key, so the source tree is safe to publish. The key never crosses USB, no command
  reads it, and a build without `FG_KEY_DIR` has the feature disabled (`status 3`). A
  leftover `fg/fg_secret.h` from older builds stops the build with an error. Rotating =
  `fg-provision.sh --rotate`, then `fg-flash.sh`.
* **Primitive.** ChaCha20-Poly1305 per RFC 8439 (Monocypher 4.0.2 on the keyboard,
  CryptoKit on the Mac). Domain separation by the first nonce byte.
* **Authenticated commands** (`STREAM_START`, `STREAM_PING`): `cmd | ctr[6] | payload | tag[16]`,
  tag = AEAD tag over `cmd|ctr|payload` with nonce `01 00 00 00 | ctr[6] | 00 00`.
  The 48-bit counter must be strictly greater than any accepted before (the host uses
  max(ms since epoch, last + 1); `STATUS` returns the keyboard's last counter so the host
  can resync). Counters only advance after the tag verifies, so forged packets cannot
  lock out the real host.
* **Session.** `STREAM_START` carries 8 host-random bytes. The keyboard refuses a session id
  it has seen recently. Frames use nonce `02 | session[8] | frame_ctr[3]`, so a
  (key, nonce) pair is never reused.
* **Frames** (`0xEC`): `ctr[3] | ciphertext[4] | tag[16]`, plaintext `pressed usage mods 0`,
  header authenticated. The host drops anything that fails the tag or whose counter does
  not increase.
* **Limits.** The stream dies by itself 3 s after the last authenticated ping
  (`FG_STREAM_TIMEOUT_MS`), after 15 min regardless (`FG_STREAM_MAX_MS`), and when the 24-bit
  frame counter runs out. It is closed by an unauthenticated `STREAM_STOP`: anyone can
  *reduce* exposure, nobody can *increase* it without the key.
* **No silent mirror.** While a stream is open, typed keys go **only** into the stream: the
  keyboard does not send them as normal key reports. A stream nobody asked for therefore
  breaks typing instead of quietly copying it. Modifiers stay native (they type nothing, and
  holding them back risks stuck modifiers), and a key held from before the stream still sends
  its native release.
* **Esc cancels.** Esc during a stream is relayed (so it still cancels a pinentry prompt),
  then the keyboard ends the stream (`ENDED` reason 5) and refuses `STREAM_START` with status
  6 for 10 s (`FG_STREAM_COOLDOWN_MS`). FocusGuard treats reason 5 as final for that password
  prompt and only opens a stream again after secure input or the steal has ended.
* **Visibility.** While a stream is open the whole keyboard pulses red and Esc is solid red.
  It is drawn last, after every override, and even under privacy blackout, and the RGB timeout
  cannot blank it, so software can neither hide nor fake it.
* **Minimal window.** FocusGuard opens the stream only while the keyboard is held by
  visionOS **and** Secure Event Input is on, and closes it the moment either stops.

### Threat model
| Attacker | Can they… | Result |
|---|---|---|
| Local process, same user | enable the stream | No: needs a valid tag. The key is only in the Keychain (behind FocusGuard's ACL) and in flash; no file on disk holds it. |
| …steal the key from a build | | Nothing to steal: builds with the key happen in a temporary directory that is deleted afterwards. |
| …read frames off the HID interface | Yes, they are broadcast to every opener | Ciphertext only; no key, no plaintext. |
| …forge or modify frames to inject keys into the Mac | | Rejected: tag + counter check. |
| …replay captured commands/frames | | Rejected: counter / session checks (they would also need to capture host→device traffic, which one process cannot). |
| …turn the stream off | Yes (`STREAM_STOP`) | Denial of the relay only; keys keep going to visionOS as before. |
| …read the key from the Keychain | Prompts the user unless it is FocusGuard | Standard Keychain ACL. |
| Someone with the keyboard in hand | dump flash, read the key | Out of scope: physical access already wins (they could just read the unencrypted native reports). |
| USB bus sniffer | | Sees native keyboard reports in clear anyway; the relay adds no new exposure. |

### Residual risks (known, accepted)
* **A stolen key still captures the first keys.** Native suppression and the red pulse make an
  unwanted stream obvious, and Esc ends it, but the keys typed before you notice have already
  been relayed. Keeping the key off disk is what prevents this; suppression limits the damage.
* **A local process that also holds Accessibility** could re-type relayed keys itself so that
  typing seems to work. The red pulse still gives it away.
* **Interrupted builds.** If `fg-flash.sh` is killed with SIGKILL, its private temporary
  directory (in your per-user `$TMPDIR`, mode 0700) is not deleted. Remove `fg-flash.*` there.
* **Timing metadata.** Frame arrival times reveal *when* keys are pressed (not which) to any
  local process while a stream is open. Limited to password-field moments.
* **FocusGuard itself** holds the key and the decrypted keys in memory while it re-types;
  a compromised FocusGuard process defeats the scheme. It needs only the Accessibility and
  Input Monitoring grants the app already requires.
* **Nonce uniqueness** relies on the host's CSPRNG for the 64-bit session id (~2⁻⁶⁴ per
  pair of sessions).
* **Cosmetic commands are open.** A local process can colour keys, send `STREAM_STOP`,
  or flip the privacy blackout/passthrough LED. None of those reveal or inject keys.

## Removed
`0xA3` (plaintext keystroke mirror) and `0xA4` (native-report suppression) no longer
exist. The old `kbdbridge` agent depended on them and does not work with this firmware.
Unchanged: `0xA1` layout, `0xA2` privacy blackout, `0xA6` passthrough LED, `0xEF`
passthrough toggle report, and QMKD (`0x01..0x07`).
